# Threat → control map

shows it working. Paths are relative to the ZIP root (`src/` holds the code). Threat names
follow the OWASP Top 10 (2021) where one applies.

## Known gaps (stated honestly)

- **IAM least privilege is limited by the AWS Academy Learner Lab.** It doesn't allow creating
  IAM roles, so the Lambda uses `LabRole` and the servers `LabInstanceProfile`, which have broader
  permissions than they need. In a real account each would get its own role, limited to
  `secretsmanager:GetSecretValue` on `cafestock/database`, `s3:GetObject` on its own prefix, and
  CloudWatch Logs.
  Least privilege is applied where the lab allows it: network (security groups per tier), users
  (Cognito groups: staff vs manager), the operating system (an unprivileged service user) and
  data (café-scoped queries).
- The app and Lambda connect to the database as its administrator. A separate, restricted
  database user for the app would be better.
- The database password isn't rotated automatically. Secrets Manager rotation would need a
  rotation Lambda plus restarting the servers.
- API Gateway reaches the internal load balancer over HTTP inside the VPC. A certificate on the
  load balancer needs a custom domain, which the Learner Lab doesn't provide.
